> Backend (40 endpoints) is done. This document plans the Next.js 16 frontend: brand, design

## 0. Brand Brief

| | |
|---|---|
| **Product name** | **Soulee** — self-learning English platform (flashcards + spaced repetition) |
| **Audience** | Self-directed learners with strong internal motivation — people who *choose* to study, not because they're forced to. A meaningful slice is preparing for **IELTS**. |
| **Emotional tone** | Youthful, poetic, calm. Not corporate-edtech, not gamified-childish. Think "a quiet study journal that believes in you," not "a leaderboard app." |
| **Core metaphor** | Growth — a soul/seed that learns and blooms. Streaks = "the flame you keep alive," known cards = "things that have taken root." |
| **Voice** | Short, warm, encouraging copy. Empty states and streak/session-end screens are where the "poetic" tone shows up most (e.g. *"Every card you plant today is a word you'll own tomorrow."*). Functional UI (forms, tables, admin) stays plain and legible — poetry is seasoning, not the whole meal. |

**Product implication:** the backend already supports free-form `tags` on study sets and tracks `popular_tags` in admin stats — no backend change needed to surface an "IELTS" or other goal-based collection on the frontend; it's just a tag filter dressed up as a curated section.

## 1. Design System

### 1.1 Color — "faded / dim green"

Desaturated sage-green as primary, warm off-white paper background (journal feel, not clinical white), deep forest-black in dark mode. Chroma stays low (~0.03–0.07) everywhere — this is the "fade/dim" instruction: no vivid/neon green anywhere in the UI.

Add as a `--sage-*` scale alongside the existing shadcn tokens in `app/globals.css`, then repoint the semantic tokens (`--primary`, `--ring`, `--sidebar-primary`, etc.) at it.

```css
/* sage scale (OKLCH) — replaces the neutral-gray scale shadcn generated by default */
--sage-50:  oklch(0.97 0.015 155);
--sage-100: oklch(0.94 0.025 155);
--sage-200: oklch(0.88 0.035 155);
--sage-300: oklch(0.80 0.045 152);
--sage-400: oklch(0.70 0.055 150);
--sage-500: oklch(0.60 0.065 148);  /* "Soulee Green" — primary */
--sage-600: oklch(0.50 0.060 148);
--sage-700: oklch(0.42 0.050 148);
--sage-800: oklch(0.33 0.040 148);
--sage-900: oklch(0.24 0.030 150);

/* warm paper neutrals (background) instead of pure white/black */
--paper-50:  oklch(0.99 0.006 90);   /* light bg */
--paper-900: oklch(0.16 0.010 145);  /* dark bg, green-tinted black, not pure gray */
```

| Semantic token | Light | Dark | Use |
|---|---|---|---|
| `--background` | `--paper-50` | `--paper-900` | page background (warm, not stark white) |
| `--primary` | `--sage-600` | `--sage-400` | CTAs, links, active nav, focus states |
| `--accent` | `--sage-100` | `--sage-800` | hover surfaces, selected chips, badges |
| `--ring` | `--sage-400` | `--sage-400` | focus ring |
| `--destructive` | keep shadcn default red | — | delete/ban/danger actions — deliberately **not** green-tinted so danger stays legible |
| streak/flame accent | small warm amber (`oklch(0.75 0.13 70)`) used *only* for the streak flame icon | — | one deliberate warm accent so the streak doesn't read as "just another green thing" |

Keep the accent count small: sage green + warm paper neutral + one amber accent for streaks. No third brand color — the poetic feel comes from typography and copy, not a busy palette.

### 1.2 Typography

- Keep **Inter** (already wired via `next/font/google`) as the UI/body font — dense screens (tables, forms, admin) need a plain, legible sans.
- Add **Fraunces** (variable serif, warm/literary) as a **display** font for: landing page hero, auth screen headline, streak/session-end celebration text, empty-state headlines, testimonial/quote-style moments. This is the "poetic" half of the pairing — used sparingly, never in dense UI.
- Wire both through `next/font/google` in `app/layout.tsx`, exposed as `--font-sans` (Inter, already present) and `--font-display` (Fraunces, new), then a `font-display` Tailwind utility for headline components.

### 1.3 Iconography & motifs

- `lucide-react` (already a dependency) — favor leaf/sprout/feather/flame glyphs for empty states, streaks, and brand touches instead of generic icons where a choice exists.
- One brand motif: a small sprout/leaf mark next to the wordmark "Soulee" (`components/brand/Logo.tsx`), reused in favicon, auth shell, and empty states.

### 1.4 Motion

- Calm, not bouncy: 150–250ms, `ease-out`, small scale/opacity transitions only (card flip, session-end reveal, streak increment).
- No new dependency required for MVP (CSS transitions are enough for flip/fade). If study-mode interactions need richer sequencing later (e.g. match-mode drag), evaluate `framer-motion` then — not installed yet, don't add speculatively.

## 2. Architecture — MVC, adapted for Next.js App Router

Next.js App Router doesn't have literal Controllers/Views as classes, so this is a **pragmatic MVC mapping**, not textbook MVC. The point is real separation of concerns with a consistent rule:

> **View never imports `apiClient`, Zustand stores, or TanStack Query directly. Only Controllers do. Model never imports React.**

| Layer | Lives in | Responsibility | Must NOT do |
|---|---|---|---|
| **Model** | `lib/api/*`, `lib/queries/*`, `lib/mutations/*`, `lib/validations/*`, `store/*` | Talk to the backend (typed request fns), cache/sync server state (TanStack Query), hold client-only global state (Zustand), validate shape (zod) | Render JSX, know about routes |
| **Controller** | `controllers/**/*` (hooks, `useXController`) | Orchestrate: call Model queries/mutations, run form validation, trigger side effects (toast, redirect, cache invalidation), expose a small plain interface to the View | Contain markup/JSX, reach into `apiClient`/axios directly (must go through Model) |
| **View** | `app/**/page.tsx`, `components/**` | Render UI from props/controller output; `page.tsx` is a thin composition root that calls one controller hook and passes results to presentational components | Fetch data, hold business state, import stores/query client |

This is exactly what's already started in the repo: `store/auth-store.ts` + `lib/mutations/auth-mutations.ts` = Model. What's missing is the **Controller** layer — right now `auth-mutations.ts` hooks would otherwise get called directly from `page.tsx`, blurring Model/View. Plan: introduce `controllers/auth/useLoginController.ts` that wraps `useLoginMutation()` + `react-hook-form` + `zod` + redirect-on-success, and have `app/(auth)/login/page.tsx` render `<LoginForm />` (View) driven by that controller.

```
User event (View)
   → Controller hook (validates, calls Model, handles side effects)
      → Model (mutation/query hits apiClient → FastAPI; or store read/write)
   ← Controller returns {data, isLoading, error, handlers} to View
← View re-renders (pure props in, callbacks out)
```

**Naming rule:** `lib/api/*.api.ts` = one function per endpoint, typed with `@repo/types`. `lib/queries` / `lib/mutations` = one `useX` hook per endpoint, built on top of `*.api.ts`. `controllers/**/useXController.ts` = one hook per *screen/interaction*, composing one or more query/mutation hooks + validation + side effects. Pages only ever import from `controllers/` and `components/`.

> **Correction made during FE-1 build:** the original draft of this plan had `app/middleware.ts` doing the protected-route redirect. That doesn't work here — as of the Phase 9.1 backend change, the refresh token is an **httpOnly cookie scoped to the API's own origin** (`apps/api/app/routers/auth.py`, `path=/api/v1/auth`, a different port than the Next.js app in dev). A same-origin Next.js middleware never receives that cookie, so it can't tell who's logged in. The real guard is client-side: `hooks/use-protected-route.ts` (`useProtectedRoute` / `useGuestRoute`) reads the Zustand auth store *after* it rehydrates (`hasHydrated`) and redirects from there — wired into `components/layout/app-shell.tsx` and `components/layout/auth-shell.tsx`, which the two `layout.tsx` files just delegate to.

## 4. State management split

| State | Owner | Why |
|---|---|---|
| Server data (sets, cards, sessions, stats, admin lists) | **TanStack Query** (`lib/queries`, `lib/mutations`) | Already the chosen data layer; cache invalidation matches REST resources 1:1 |
| Auth session (user, access token, hydration flag) | **Zustand** `auth-store.ts` (existing) | Needs to persist across reloads and be read outside React tree (`api-client.ts` interceptor) |
| Ephemeral UI state (sidebar open, theme, in-progress study session) | **Zustand**, small dedicated stores | Local, doesn't belong in server cache, doesn't need persistence (except theme) |
| Form state | **react-hook-form + zod**, inside Controllers | Already a dependency; validation schemas live in `lib/validations` (Model), wiring lives in Controller |

## 6. Phased roadmap

Restructures the existing Phase 9.1–9.6 breakdown around the design-system-first + MVC layering above. Each feature phase touches all three layers (Model → Controller → View, in that build order).

| Phase | Scope | Key deliverables |
|---|---|---|
| **FE-0 — Foundation** | Design system + brand | Sage-green tokens in `globals.css`, Fraunces font wired, `components/brand/Logo.tsx`, `AuthShell` + `AppShell` layouts, rename metadata/title to "Soulee", `next-themes` dark-mode toggle |
| **FE-1 — Auth (~9.1)** | Finish what's scaffolded | `controllers/auth/*`, `lib/validations/auth.schema.ts`, `LoginForm`/`RegisterForm` views, client-side route guards (`hooks/use-protected-route.ts` via `AppShell`/`AuthShell`), toast feedback on success/error |
| **FE-2 — Dashboard (~9.2)** | Home screen | `stats.api.ts` + `useStatsOverviewQuery`, `StreakBadge`, recent-sets grid, empty-state copy (poetic tone lives here) |
| **FE-3 — Folders & Sets & Cards (~9.3)** | Full CRUD + reorder | Folder/Set CRUD (Model→Controller→View for each), tag-filter chips (IELTS collections), card drag-drop reorder (`@dnd-kit`), image upload for avatar/card |
| **FE-4 — Study modes (~9.4)** | The core learning loop | `useStudySessionController` (mode-agnostic session lifecycle), 4 View components: `Flashcard`, `LearnQualityPicker` (1–5), `TestQuestion`, `MatchBoard` |
| **FE-5 — Stats & History (~9.5)** | Progress visibility | `recharts`-based `SessionsChart`, known/learning/not-started breakdown, per-set stats page |
| **FE-6 — Admin (~9.6)** | Ops/moderation UI | Admin dashboard, user table (ban/promote/reset), set moderation, `ConfigForm` for `SystemConfig` (7 fields), admin stats charts |
| **FE-7 — Polish (10.2)** | Cross-cutting QA | Full E2E flow pass (register → set → study → stats; admin ban/moderate flow), responsive + a11y pass, motion/copy polish |
